---
name: ldo-ship
description: Ship the pipeline's changes — branch, commit, push, PR, optional squash-merge — with the review report as the PR body
---

Ship what the pipeline just produced. This is interactive: you propose, the operator confirms at every irreversible step. Nothing is pushed, merged, or deleted without a yes.

## Prerequisites

- There are uncommitted changes in the working tree (the pipeline's output).
- `git` is available and the repo is clean of unrelated work — check `git status`. If the tree has changes the pipeline didn't make, stop and say so.
- `gh` is authenticated (`gh auth status`) if a PR is wanted.

## The flow

### 1. Branch

Generate a branch name from the task: kebab-case, 3-6 words, prefixed with nothing fancy.

```
add-rate-limiting-to-api
fix-session-token-refresh
refactor-auth-middleware
```

Show it. `git checkout -b <name>` only after the operator agrees.

### 2. Commit

Generate the commit message from the plan's summary and the verdict. Format:

```
<type>: <one-line summary, imperative mood, ≤72 chars>

<body: what changed and why, 2-4 lines>
```

Types: `feat`, `fix`, `refactor`, `docs`, `test`, `chore`. The summary comes from the plan; the body from the verdict's summary plus any notable deviations.

Show the full message. `git add` the files the pipeline touched (from the Coder's `files_changed` or `git diff --name-only`), then `git commit`. Don't `git add -A` — only what this run produced.

### 3. Push

`git push -u origin <branch>`. One line of confirmation.

### 4. PR

Create the PR with `gh pr create`. The **body is the review report** — the receipts are why this PR is safe to merge:

```markdown
## What

<plan summary, one paragraph>

## Verification

| Criterion | Status | Evidence |
|-----------|--------|----------|
| ... | passed | <captured output> |

## Attacks

| Vector | Outcome |
|--------|---------|
| ... | held |

## Security

<threat model findings and mitigations, or "none">

---
Generated by LDO. Reviewer: Opus. Coder: Sonnet. N pass(es).
```

If a review report file exists at `docs/reviews/`, read it and use its content. Otherwise reconstruct from the workflow result.

Show the PR title and body. Create on confirm.

### 5. Squash-merge

**Interactive mode:** after the PR is open and CI (if any) is green, offer:

> Squash-merge into `<default-branch>` and delete the branch? Confirm.

`gh pr merge --squash --delete-branch`. Only on explicit yes. If the operator says "not yet", the PR stays open.

**Auto-merge mode:** check whether CI is configured (`.github/workflows/` or the PR's checks). If CI exists, wait for it to finish — `gh pr checks --watch`, or poll `gh pr checks --json state` every 30s. On green: `gh pr merge --squash --delete-branch`. On red: stop, report which checks failed, leave the PR open. If no CI: merge immediately.

## Modes

**Interactive (default).** Confirm at each step. Use when the change matters and you want a checkpoint.

**Auto** (`auto`, `--yes`, "ship it without asking"). Skip all confirmations — branch, commit, push, PR in one pass. Still stops on errors: push rejected, PR creation fails, unrelated files in the tree.

**Auto-merge** (`auto-merge`, "ship and merge"). Everything in auto, plus squash-merge at the end. If CI is configured, waits for it; merges on green, stops on red. If no CI, merges immediately. Deletes the branch after.

Pick the mode from what the operator asks. "Ship it" with no qualifier = interactive. "Ship it, no questions" or "auto" = auto. "Ship and merge" or "auto-merge" = auto-merge.
